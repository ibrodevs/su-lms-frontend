# PROMPT ДЛЯ ИИ: UX/UI структура платформы Bilim Ordo

## Название проекта

Платформа называется:

# Bilim Ordo

Смысл названия:

- **Bilim** — знание
- **Ordo** — центр / пространство / главное место

Общий смысл: **Bilim Ordo — центр знаний**.

Платформа должна восприниматься как современная образовательная цифровая система, где студенты изучают материалы, проходят тесты и отслеживают прогресс, а учителя и администраторы управляют учебным процессом через веб-панель.

---

## Важное уточнение по стилю

В этом промте нужно проработать **структуру, архитектуру экранов, пользовательские роли, UX-flow, логику интерфейса и состав экранов** для мобильного приложения и админ-панели.

**Финальный визуальный стиль, UI-направление, референсы, настроение дизайна, типографику, компоненты, визуальные акценты и детальные правила оформления я передам отдельно в файле `Design.md`.**

Не придумывай финальный визуальный стиль самостоятельно. Используй только базовое направление по темам:

- Светлая тема: **синий + белый**
- Темная тема: **темный фон + синий акцент**

Главная задача — сделать продуманную UX/UI-структуру экранов, ролей, разделов и пользовательских сценариев, чтобы потом на основе `Design.md` можно было сделать полноценный современный дизайн.

# 1. Описание проекта

Нужно спроектировать образовательную платформу **Bilim Ordo**, которая состоит из:

1. **Мобильного приложения для студентов**
2. **Веб-админ-панели для администратора**
3. **Веб-кабинета учителя внутри админ-панели**

Платформа нужна для того, чтобы студенты могли заходить в приложение по специальному Student ID, видеть доступные предметы, изучать уроки, смотреть видео, читать текстовые материалы, открывать файлы, проходить модули/тесты и получать результаты.

Контент в приложение добавляют учителя через админ-панель. Администратор управляет предметами, учителями, студентами, группами и доступами.

---

# 2. Главная идея Bilim Ordo

**Bilim Ordo** — это единое цифровое пространство обучения.

Студент получает простой доступ к материалам через мобильное приложение.  
Учитель создает и публикует уроки, материалы и тесты.  
Администратор управляет всей учебной структурой: пользователями, группами, предметами и назначениями.

Платформа должна быть:

- понятной для студентов;
- удобной для учителей;
- контролируемой для администратора;
- масштабируемой;
- современной;
- аккуратной;
- поддерживающей светлую и темную тему;
- готовой к расширению в будущем.

---

# 3. Основная логика платформы

## 3.1. Студент

Студент входит в мобильное приложение через специальный **Student ID**.

До этого администратор заранее создает студента в админ-панели. После создания каждому студенту назначается уникальный Student ID.

После входа студент видит:

- свои предметы;
- уроки внутри предмета;
- учебные материалы урока;
- видео;
- текстовые материалы;
- прикрепленные файлы;
- модули/тесты;
- результаты тестов;
- личный прогресс.

Студент может проходить тест только **один раз**. После прохождения теста он сразу видит оценку или результат.

---

## 3.2. Учитель

Учитель входит в свою часть админ-панели через **логин и пароль**.

Учитель может:

- видеть только свои предметы;
- создавать уроки;
- редактировать свои уроки;
- добавлять видео к уроку;
- добавлять текстовое описание урока;
- прикреплять файлы к уроку;
- создавать модули/тесты;
- добавлять вопросы и варианты ответов;
- указывать правильные ответы;
- публиковать или скрывать уроки и тесты;
- смотреть результаты студентов;
- видеть прогресс студентов по своим предметам.

Учитель не должен иметь доступ к глобальным настройкам платформы, управлению другими учителями или системным настройкам.

---

## 3.3. Администратор

Администратор управляет всей системой **Bilim Ordo**.

Админ может:

- создавать предметы;
- редактировать предметы;
- назначать учителей на предметы;
- создавать учителей;
- задавать логин и пароль для учителя;
- создавать студентов;
- генерировать или задавать Student ID;
- создавать студенческие группы;
- добавлять студентов в группы;
- назначать предметы группам или отдельным студентам;
- видеть общую статистику;
- смотреть активность студентов;
- смотреть результаты тестов;
- управлять контентом;
- редактировать или удалять данные.

# 4. Пользовательские роли

Нужно продумать интерфейс под 3 основные роли.

---

## 4.1. Student

Платформа: мобильное приложение.

Основные действия:

- вход по Student ID;
- просмотр предметов;
- изучение уроков;
- просмотр видео;
- чтение текстовых материалов;
- просмотр и скачивание файлов;
- прохождение тестов;
- просмотр результата;
- просмотр своего прогресса;
- переключение светлой/темной темы;
- выход из аккаунта.

---

## 4.2. Teacher

Платформа: веб-админ-панель.

Основные действия:

- вход по логину и паролю;
- просмотр назначенных предметов;
- создание и редактирование уроков;
- загрузка материалов;

- просмотр результатов студентов;

- управление только своим учебным контентом.

---

## 4.3. Admin

Платформа: веб-админ-панель.

Основные действия:

- управление всеми пользователями;
- управление предметами;
- управление группами;
- назначение учителей;
- назначение предметов;
- просмотр аналитики;
- контроль учебного процесса;
- управление доступами;
- просмотр всей активности.

# 5. Мобильное приложение Bilim Ordo для студентов

Нужно спроектировать экраны мобильного приложения.

---

## 5.1. Splash screen

Экран запуска приложения.

На экране:

- название **Bilim Ordo**;
- короткий tagline, например:
  - “Digital Learning Platform”
  - “Your learning space”
  - “Learn. Practice. Progress.”
- loading state.

---

## 5.2. Экран входа по Student ID

Цель: дать студенту простой способ войти в приложение.

На экране должно быть:

- название **Bilim Ordo**;
- поле ввода Student ID;
- кнопка “Войти”;
- состояние ошибки, если ID неверный;
- состояние загрузки;
- короткая подсказка: “Введите Student ID, который вы получили от администратора или учителя”.

UX-логика:

- если ID существует — студент попадает на главный экран;
- если ID неверный — показать понятную ошибку;
- если студент заблокирован или неактивен — показать отдельное сообщение;
- если нет интернета — показать ошибку подключения.

---

## 5.3. Главный экран студента / Dashboard

Цель: показать студенту его учебное пространство.

На экране должны быть:

- приветствие: имя студента;
- название платформы **Bilim Ordo** в header или профиле;
- краткая статистика:
  - количество предметов;
  - пройденные уроки;
  - доступные тесты;
  - средний результат;
- список предметов;
- блок “Продолжить обучение”;
- последние открытые уроки;
- уведомления или важные сообщения, если нужно.

Карточка предмета должна показывать:

- название предмета;
- имя учителя;
- количество уроков;
- количество тестов;
- прогресс прохождения;
- статус:
  - “Не начато”
  - “В процессе”
  - “Завершено”

---

## 5.4. Экран списка предметов

Цель: показать все предметы, доступные студенту.

На экране:

- поиск по предметам;
- список предметов;
- фильтр по статусу:
  - Все
  - Не начато
  - В процессе
  - Завершено
- карточки предметов.

Карточка предмета:

- название;
- описание;
- учитель;
- прогресс;
- количество уроков;
- количество тестов;
- кнопка “Открыть”.

---

## 5.5. Экран предмета

Цель: показать все уроки и модули внутри выбранного предмета.

На экране должны быть:

- название предмета;
- имя учителя;
- описание предмета;
- общий прогресс по предмету;
- список уроков;
- список тестов/модулей;
- фильтр или вкладки:
  - Все
  - Уроки
  - Тесты
  - Завершено

Карточка урока:

- название урока;
- краткое описание;
- статус прохождения;
- наличие видео;
- наличие файлов;
- кнопка “Открыть”.

Карточка теста:

- название теста;
- количество вопросов;
- статус:
  - доступен;
  - пройден;
  - недоступен;
- результат, если тест уже пройден;
- отметка “1 попытка”.

---

## 5.6. Экран урока

Цель: аккуратно и удобно показать учебный материал.

Урок может содержать:

- видео;
- текстовый материал;
- прикрепленные файлы;
- дополнительные материалы.

Структура экрана:

### Верхняя часть

- название урока;
- название предмета;
- статус урока;
- прогресс/отметка завершения.

### Видео-блок

- встроенный видеоплеер;
- состояние, если видео не добавлено;
- возможность открыть видео на весь экран.

### Текстовый блок

- заголовки;
- основной текст;
- форматированный контент;
- списки;
- выделения;
- цитаты или важные заметки, если нужно.

### Файлы

- список прикрепленных файлов;
- иконка типа файла;
- название файла;
- размер файла;
- кнопка открыть/скачать.

### Нижняя часть

- кнопка “Отметить как изучено”;
- кнопка “Следующий урок”, если доступен;
- кнопка “Назад к предмету”.

UX-логика:

- студент может открыть урок несколько раз;
- после изучения он может отметить урок как завершенный;
- если урок уже завершен, показывать статус “Завершено”.

---

## 5.7. Экран теста / модуля

Цель: дать студенту возможность пройти тест один раз.

Перед началом теста показать:

- название теста;
- предмет;
- количество вопросов;
- правила:
  - только одна попытка;
  - после отправки ответы нельзя изменить;
  - результат будет показан сразу;
- кнопка “Начать тест”.

Во время теста:

- показывать вопрос;
- варианты ответов;
- индикатор прогресса: например, “Вопрос 3 из 10”;
- кнопки “Назад” и “Далее”, если разрешено;
- кнопка “Завершить тест”;
- предупреждение перед финальной отправкой.

Типы вопросов на первом этапе:

- один правильный ответ;
- несколько правильных ответов.

Можно заложить как будущую возможность:

- текстовый ответ;
- вопрос с файлом;
- вопрос с изображением.

После завершения:

- показать результат;
- количество правильных ответов;
- процент;
- оценку;
- статус: “Сдано” / “Не сдано”, если есть проходной балл;
- список вопросов с правильными/неправильными ответами, если это разрешено настройками.

Очень важно:

- после прохождения тест становится недоступным для повторного прохождения;
- вместо кнопки “Начать” студент видит “Тест уже пройден” и свой результат.

---

## 5.8. Экран результата теста

На экране:

- название теста;
- предмет;
- дата прохождения;
- итоговый балл;
- процент;
- количество правильных ответов;
- количество неправильных ответов;
- статус;
- кнопка “Вернуться к предмету”.

Если разрешено показывать ответы:

- список вопросов;
- ответ студента;
- правильный ответ;
- объяснение, если оно есть.

---

## 5.9. Экран результатов студента

Цель: показать студенту его успеваемость.

На экране должно быть:

- общий прогресс;
- список предметов;
- результаты тестов;
- дата прохождения;
- оценка;
- процент;
- статус.

Можно добавить:

- график прогресса;
- список завершенных уроков;
- список непройденных тестов;
- фильтр по предмету.

---

## 5.10. Профиль студента

На экране профиля:

- имя студента;
- Student ID;
- группа;
- список предметов;
- настройки темы:
  - светлая;
  - темная;
  - системная;

Админ может видеть все уроки, а учитель — только свои.

Таблица уроков:

- название урока;
- предмет;
- автор/учитель;
- наличие видео;
- количество файлов;
- дата создания;
- статус;
- действия.

Форма создания/редактирования урока:

- выбрать предмет;
- название урока;
- краткое описание;
- основной текст;
- видео:
  - загрузка файла;
  - или ссылка на видео;
- прикрепленные файлы:
  - PDF;
  - DOC/DOCX;
  - PPT/PPTX;
  - изображения;
  - другие учебные материалы;
- порядок урока внутри предмета;
- статус:
  - черновик;
  - опубликовано;
  - скрыто.

## 8.7. Управление тестами / модулями

Таблица тестов:

- название теста;
- предмет;
- количество вопросов;
- автор;
- дата создания;
- статус;
- количество прохождений;
- средний результат;
- действия.

Форма создания теста:

- выбрать предмет;
- название теста;
- описание;
- проходной балл, если нужен;
- включить/выключить показ правильных ответов после прохождения;
- количество попыток: по умолчанию 1;
- статус публикации.

Конструктор вопросов:

- добавить вопрос;
- тип вопроса:
  - один правильный ответ;
  - несколько правильных ответов;
- текст вопроса;
- варианты ответа;
- отметить правильный ответ;
- баллы за вопрос;
- удалить/дублировать вопрос;
- изменить порядок вопросов.

Важно:

- тест можно пройти только один раз;
- система должна хранить результат;
- после прохождения тест нельзя пройти повторно.

---

## 8.8. Результаты и аналитика

Раздел результатов должен быть доступен админу и учителю.

Для админа:

- все студенты;
- все группы;
- все предметы;
- все тесты.

Для учителя:

- только его предметы;
- только студенты, которые проходят его предметы;
- только тесты, созданные им или относящиеся к его предметам.

Фильтры:

- предмет;
- группа;
- студент;
- тест;
- дата;
- статус;
- диапазон оценки.

Таблица результатов:

- студент;
- группа;
- предмет;
- тест;
- результат;
- процент;
- дата прохождения;
- статус;
- попытка.

Страница результата:

- ответы студента;
- правильные ответы;
- неправильные ответы;
- итоговый балл;
- время прохождения, если будет добавлено;
- дата прохождения.

# 10. UX-flow

Нужно обязательно продумать следующие пользовательские сценарии.

---

## 10.1. Сценарий студента

1. Студент открывает приложение Bilim Ordo.
2. Вводит Student ID.
3. Попадает на главный экран.
4. Видит свои предметы.
5. Выбирает предмет.
6. Открывает урок.
7. Смотрит видео.
8. Читает текст.
9. Открывает файлы.
10. Отмечает урок как изученный.
11. Открывает тест.
12. Читает правила.
13. Проходит тест.
14. Подтверждает отправку.
15. Сразу получает результат.
16. Видит тест как завершенный.
17. Не может пройти этот же тест повторно.

---

## 10.2. Сценарий администратора

1. Админ входит в Bilim Ordo Admin.
2. Создает предмет.
3. Создает учителя.
4. Назначает учителя на предмет.
5. Создает группу.
6. Создает студентов.
7. Генерирует Student ID.
8. Назначает студентов в группу.
9. Назначает предмет группе.
10. Проверяет статистику и результаты.

---

## 10.3. Сценарий учителя

1. Учитель входит в Bilim Ordo Admin.
2. Видит свой Teacher Dashboard.
3. Видит свои предметы.
4. Открывает предмет.
5. Создает урок.
6. Загружает видео, текст и файлы.
7. Создает тест.
8. Добавляет вопросы и ответы.
9. Указывает правильные ответы.
10. Публикует урок и тест.
11. Смотрит результаты студентов.

# 14. Важные бизнес-правила

1. Платформа называется **Bilim Ordo**.
2. Студент входит только через Student ID.
3. Student ID создается администратором.
4. Student ID должен быть уникальным.
5. Студент не регистрируется самостоятельно.
6. Учитель входит через логин и пароль.
7. Админ создает учителей и назначает их на предметы.
8. Админ создает студентов и группы.
9. Админ назначает предметы группам или студентам.
10. Учитель может управлять только своими предметами.
11. Урок может содержать видео, текст и файлы.
12. Тест создается учителем или админом.
13. У теста может быть несколько вопросов.
14. У вопроса есть варианты ответов.
15. У каждого вопроса есть правильный ответ.
16. Студент может пройти тест только один раз.
17. После завершения теста студент сразу видит результат.
18. Результаты сохраняются и доступны учителю/админу.
19. Интерфейс должен поддерживать светлую и темную тему.
20. Финальный стиль будет передан отдельно в `Design.md`.
